# BEATROOTS browser patcher

Plain HTML, CSS and JavaScript; no dependencies, backend, build step, or uploads.
This version matches the current standalone **v10c** Python release.

Open `index.html` in a current browser, or serve the parent directory:

```sh
python3 -m http.server 8765 --directory volca-beats-glitch
```

Then visit http://localhost:8765/browser/. For hosting, serve over HTTPS and keep
all five application files together. A shortened guide is embedded in index.html, with controls and references.
Python and standalone installation instructions stay in the parent README. Never publish the official firmware or generated WAV.
SHA-256 requires browser Web Crypto support (HTTPS, localhost, or a browser that
supports it for local files); unsupported environments report an error.

Choose the original unzipped Korg 1.04 WAV and press Patch firmware. Only after
all transport, firmware, round-trip and SHA-256 checks pass does the page expose
the player and download. Everything stays in memory. There are no remote scripts,
fonts, analytics or requests carrying firmware; CSP disables fetch connections.

Playback is explicit, starts at zero, and has no seeking, looping or autoplay.
The output is byte-identical to Python. Browser-to-device transfer has been
confirmed by the project author. Use the installation instructions and confirm End on the
instrument. A finished player is not proof of a completed firmware installation.

## Verification and release updates

From the repository root, run `node tools/test_browser_patcher.cjs`. An optional
second argument points to a WAV generated by Python for byte-for-byte comparison.
The suite checks exact output, invalid inputs, packet/CRC corruption and changed
patch rejection. Browser QA also verified local file selection, successful
patching, loaded duration, download-link creation and no automatic playback.
The project author subsequently confirmed playback with a connected Volca.

`release.js` contains only replacement spans and hashes copied from the Python
patcher. When updating firmware, regenerate that data from the Python constants,
update visible version labels and rerun parity tests. Do not substitute a full
firmware image or remove validation checks.

The embedded guide is generated from the parent README. After editing it, run
`node tools/sync_browser_readme.cjs /path/to/marked/lib/marked.esm.js` from the
repository root (or omit the path when `marked` is installed locally). The
browser needs no Markdown library or network fetch to display the guide.
